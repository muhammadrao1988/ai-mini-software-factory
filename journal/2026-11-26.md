## What I decided, and why
Every later step needs this. Before the judge can test a product over HTTP, the factory must be able to start that product's code as a real web service. It must also fail clearly when the code cannot load, and shut the service down cleanly afterwards. The step is small and uses only the standard library. It can be fully tested with no AI, using only the local machine.

I chose plain WSGI over FastAPI for two reasons. The goal file says standard library only for the factory, and the planner's rules today also say standard library only. So this works now, without adding outside packages.

## What could go wrong
- The child process writes a log line for every request. If its error output goes to a pipe that nobody reads, the pipe fills up and the service freezes. That output must go to a temporary file instead.
- The code cannot load (wrong module or missing name). If the factory only waits for the port, it hangs until the timeout. It must notice that the child has exited and fail fast, with the child's error text.
- The service is not ready yet when the handle comes back, so the first request is refused. start_service must wait until a connection works.
- The child imports `app` from the factory folder or the current folder instead of the product's code folder. The child must run from the code folder, with that folder first on its import path.
- Port clashes: two services must get two different free ports.
- A crashing request kills the server. A WSGI app error must give a 500 answer, and the next request must still work.
- stop() is called twice, or after the context manager has ended. This must not raise an error.
- Orphan processes stay alive after an error. Every failure path must kill the child.
- The existing tests/test_factory.py may already fail because tasks/ and reference/ are missing. The builder must not 'fix' those tests by weakening them.

## What the builder said
I added `start_service(code, entry="app.web:application", wait=10.0)` and a small `Service` class to `factory.py`, using only the standard library (the one new import is `socket`). The function rejects a bad `entry` with `ValueError` before starting anything, picks a free port, and starts a child Python process that runs from `code` and serves the app with `wsgiref`. The child's output goes to a temporary file instead of a pipe. It returns a `Service` (`url`, `process`, `stop()`, and with-block support) once the port answers. If the child exits early or doesn't answer within `wait` seconds, it kills the child and raises `RuntimeError` with the last 500 characters of the child's output. `stop()` is safe to call more than once. New tests in `tests/test_service.py` cover:
- the bad entries
- serving and stopping
- a 500 that leaves the service still answering
- two services running at once
- a missing module failing fast with "No module named 'nothere'"
- a missing attribute
- a service that never listens being killed after the wait

All 20 tests pass, and I didn't change the judge, the planner or any existing test.
