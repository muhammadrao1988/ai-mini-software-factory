## What I decided, and why
The goal's proof is hidden tests that call the product over HTTP. That cannot happen until the judge itself runs the service and tells the tests where it is. This is the smallest link between yesterday's `start_service` and the planner work planned for tomorrow. It uses only the standard library, and it can be fully checked on the local machine without any AI.

## What could go wrong
- The service keeps running after the judge returns, or when the tests crash. The judge must stop it in a `finally` block, before it deletes its temporary folder.
- The service runs the agent's workspace instead of the judge's clean copy. Then files the agent left behind could change the verdict. The service must be started from the judge's `code` copy.
- A PRODUCT_URL value left in the outer environment reaches tests when no service was started, so they call some other, stale service. Without `serve`, the judge must remove PRODUCT_URL from the test environment.
- The app cannot load. If the judge raised an error, the whole build would crash. It must instead count one failure named COULD_NOT_RUN, with the reason in the log, so the agent gets a retry.
- A bad `serve` value is a setup mistake, not the agent's fault. It must raise ValueError right away, before anything is started.
- web.txt has blank lines, extra spaces, or wrong content. Blank lines and spaces must be ignored, and bad content must raise ValueError.
- Existing callers of pytest() and run_task() must keep working unchanged. The new inputs are optional and default to None.
- The existing tests/test_factory.py may already fail because tasks/ and reference/ are missing. Do not change or weaken those tests.
